Vivu acompaña a estudiantes con misiones pequeñas, recursos y recomendaciones. Este informe explica qué existe hoy y qué necesita cuidado antes de crecer.

La idea principal

Hay funcionalidades y pruebas útiles, pero varias piezas guardan información solo mientras están encendidas y mantienen reglas duplicadas. El sistema debe consolidar sus conexiones y proteger sus datos antes de usarse con información real.

Evaluación documental del código en el corte 4b330ad, 13 de noviembre de 2026. No es una certificación ISO ni una prueba de producción.

Lo que ya existe

Autenticación, perfil y consentimiento, misiones, recursos, encuestas y recomendaciones tienen implementaciones y pruebas en el repositorio.

Lo que aún es una base

Los servicios de acompañamiento y analítica exponen salud, pero no se observó una API de negocio implementada en ellos.

Infraestructura preparada

Docker Compose configura PostgreSQL y RabbitMQ. Configurarlos no significa que las funciones observadas guarden datos allí o intercambien eventos: eso necesita integración y pruebas.

02 · Estado actual

Lo que merece atención

01

Memoria temporal

Los datos de varios dominios y las sesiones viven en la memoria del proceso. Un reinicio puede borrarlos y varias instancias pueden mostrar resultados distintos.

02

Seguridad de desarrollo

Hay cuentas y secretos de ejemplo. Son útiles para prototipar, pero necesitan controles y secretos gestionados antes de un entorno compartido.

03

Reglas repetidas

La web, el gateway y servicios contienen reglas o estados similares. Una mejora en un lugar no garantiza el mismo resultado en otro.

04

Salud limitada

Una respuesta de preparación indica que el proceso responde, pero las comprobaciones revisadas no verifican la base de datos ni el broker.

Estos son riesgos observados en el código, no incidentes confirmados en producción.

03 · Calidad y cuidado

¿Qué significa calidad aquí?

La revisión utiliza el modelo ISO/IEC 25010:2023 como guía y escenarios de calidad inspirados en Software Architecture in Practice.

Confianza y privacidad

Guardar el consentimiento de manera duradera, respetar su retiro y controlar quién puede consultar información sensible son condiciones para un uso responsable.

Continuidad y claridad

Si una persona completa una misión y se reinicia el sistema, debería conservar su progreso. Si una recomendación no es adecuada, debería poder rechazarla y entender su origen.

Experiencia y evolución

El acceso con teclado, el desempeño bajo carga y la facilidad de cambiar reglas necesitan mediciones y objetivos acordados. Las pruebas existentes son un punto de partida, no una garantía integral.

Aún no se midieron tiempos de respuesta, accesibilidad con usuarios, recuperación ni seguridad mediante pruebas especializadas. No se asignan calificaciones sin esos datos.

04 · Camino propuesto

Avanzar con tranquilidad

Primero · antes de datos reales

Proteger y conservar

Retirar credenciales de ejemplo de entornos compartidos, definir el ciclo de vida de datos y construir persistencia y recuperación verificables.

Después · antes de ampliar el piloto

Conectar y comprobar

Asignar un responsable a cada regla, integrar web y servicios con contratos claros y probar permisos, reinicios y fallos entre componentes.

Luego · mejora continua

Medir y aprender

Decidir el papel de los eventos, medir desempeño y accesibilidad, observar el funcionamiento y revisar las decisiones con el equipo y las personas usuarias.
